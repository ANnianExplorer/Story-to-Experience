# 三视角自审与评审

本清单适用于开发者自身或实际评审人，不要求自动创建三个 Agent。一次检查包含三个视角不等于三位独立审核，自动自审不能给出“已安全完整”的保证。

## 开发者视角：行为是否正确

- 需求/任务/验收是否对应，输入、输出、失败、取消、重试是否明确？
- 引擎是否纯函数？ABC/BAC 等独立预期是否成立？非法输入是否原子拒绝？
- UI 空态/错误/冲突/权限/未知状态是否真实？
- 检查是否实际运行？是否有未跑项却被写成通过？

## 组长视角：能否集成和维护

- 是否遵守五层依赖与逻辑数据所有权？公共类型是否派生？
- 模块任务依赖、活动任务、并发修改、旧 Worker 迟到提交是否覆盖？
- 需求、迁移、API 消费者、事件、测试、文档是否一起更新？
- 是否保护用户已有修改？有没有无关重构和重复事实源？

## 技术负责人视角：能否交付及承担风险

- 有哪些真实 Provider、数据库、浏览器、手机、恢复证据？哪些仍是模拟？
- 来源支持和内容审核覆盖是否充分？模型有没有越权发布能力？
- 分享撤销是否覆盖图片/规格？正式包有无私有资料/密钥？许可是否有效？
- 预算、失败成本、回退、备份恢复和生产身份是否可复查？

## 输出

每个发现记 priority、关联需求/规则、具体证据、影响、修复与验证。P0/P1 阻断适用发布，不能只写“已自审”。无发现写明审查范围和未覆盖项；风险接受记录授权人、理由、范围、有效期及跟踪任务。

完整交付采用 [任务与证据模板](templates/task-and-evidence.md)。领域内容仍需实际创作者/审核人决定；教育收益仍需适当研究设计。
