# 文档治理与可执行范围

## 唯一真相

CLAUDE 管红线，ADR 管选择，SPEC 管外部行为，SDD 管实现与任务，registry 管功能状态，quality/reports 管冻结证据。原方案和历史报告不成为第二份运行规范；正文变更同步链接，不复制内容。

功能采用一份 SPEC 和一份 SDD；只有需求、契约、UI、状态机已复杂到互相阻碍时才拆目录包。每块保留 README 核心目录。示例不能包含真实私有原文、令牌或密钥。

## 编号与维护

Fxx 功能、Rxx 需求、Txx 任务、ATxx 验收；ADR 四位序号；Gxx 门禁；R01—R10 是根红线。编号停用后保留历史不复用。新增功能同时更新 registry、SDD/SPEC 功能目录和 docs 总目录。

根文档/总目录注明日期和状态，功能事实更新通过 registry.updated 与版本控制记录；代码落地后给每功能明确负责人。当前没有实际团队，不编造 owner 姓名或签字。对无效/过时文档先标 superseded 并链接替代，再归档。

## 本地检查

`python scripts/check_docs.py` 检查 Markdown 本地链接/锚点、围栏、JSON 语法、功能文件与 ID 覆盖、ADR 引用、依赖环、状态需要的路径/证据存在性、红线/门禁编号。它不能判断语义是否正确，也不验证报告真实性；这仍需评审和实际执行。

`python scripts/check_contracts.py` 检查 Schema 自身、合成正例、八项反例、部分静态语义和固定排序预期；不作为生产引擎，不做全部可达性搜索。类型派生/跨语言 JCS fixtures 在应用代码落地时接入 G03。

外部链接不由本地脚本联网检查；文档引用官方资料时记录用途与核对日期。这些检查的远端执行状态以平台实际记录为准。

前端基线新增 `python scripts/check_ui.py`：检查 Token、指定颜色对比度、动效数值上界和 CSS 派生一致性，并已接入 CI 定义。它不替代生产 React 构建、真实布局/交互/减弱模式或全站无障碍验收。
