# F05 SPEC：分层检查、自动试玩与有限修复

> 文档基线；需求已定义，业务验收未执行。设计见 [SDD](../../sdd/features/F05-validation-repair.md)。

## 范围

用可复查证据区分结构合法、逻辑可完成、真实界面可操作和内容待审；不判断自动趣味性或普遍教育效果。

## 需求

| 需求 ID | 需求 | 必须满足的行为 |
|---|---|---|
| F05-R01 | 分层报告 | 分别记录结构、引用/语义、状态、浏览器检查结论与范围；没有执行的层为 not_run；技术 passed 要求所有必需层通过。 |
| F05-R02 | 完整状态结论 | 枚举可达 scene+flags；至少一条完成路径；所有可达非终止状态仍有完成后续；完成态满足必要任务。 |
| F05-R03 | 真实 UI 试玩 | 用浏览器通过正常热点、排序、选择、提示、来源和重玩完成关键路径；只读状态辅助断言，不直接写完成标记。 |
| F05-R04 | 有限受限修复 | 报告 code/object_id/expected/actual/evidence/repairable；最多两轮补丁；重跑全部结构/来源/状态和受影响浏览器路径及一条完整路径。 |

## 验收计划

| 验收 ID | 关联需求 | 场景及可观察预期 |
|---|---|---|
| F05-AT01 | F05-R01 | 缺失场景、无效引用、循环偏序分别定位对象/字段；仅 Schema 通过不能技术通过。 |
| F05-AT02 | F05-R02 | 注入拿不到的必要标记为 failed；可达死路给路径；超过时间/状态上限为 inconclusive。 |
| F05-AT03 | F05-R03 | 保存桌面和手机尺寸 Chromium trace/截图；按钮缺失或排序不可提交必须失败。 |
| F05-AT04 | F05-R04 | 第三轮不调用模型；补丁改测试器/删必要目标/编造证据被拒；稳定版保持原哈希。 |

## 契约与失败行为

上限为 inconclusive，不冒充无解；真正死路为 failed；引擎/解析器缺陷转开发；资料不足等待输入；超过两轮停止。

通用字段、HTTP 错误和权限取 [公共 API](../api.md)、[状态机](../state-machines.md)、[安全规格](../security.md)；体验执行取 [DSL 契约](../experience-spec.md)。任何新增机制/状态/权限需同步这些规格与相关验收。

## 完成边界

每条 AT 必须记录环境、输入/版本哈希、命令或操作、预期/实际和报告路径。模拟、静态检查、真实 Provider 与真实浏览器证据分开；当前只定义计划，不声称功能通过。状态仅更新 [登记表](../../feature-registry.json)。
