# F10 SPEC：多 Agent 规划与协作

> 用户纠正后的核心设计范围，业务实现 planned。设计见 [SDD](../../sdd/features/F10-multi-agent.md)，决策见 [ADR-0010](../../adr/0010-multi-agent-and-conversation.md)。

## 需求与验收

| 需求 ID | 必须满足的行为 |
|---|---|
| F10-R01 | Coordinator 根据创作者意图生成有依赖、输入输出和完成条件的计划；按权限调度 Evidence/Designer/Builder/Review/Repair，记录独立 agent_id、task_id、profile_version、工具白名单和上下文范围。 |
| F10-R02 | 交接使用版本化结构消息与不可变产物引用；Agent 不共享可随意覆盖的大消息列表或裸数据库写权限。跨项目、过期版本或错误 Schema 交接拒绝。 |
| F10-R03 | 候选审校与确定性检查可并行，最终汇合后再推进；子任务超时、取消、重启、重复回调有幂等和 fencing；取消传播到未启动子任务和新调用。 |
| F10-R04 | 真实轨迹可展示计划、委派、工具、结果、错误、耗时/费用与恢复，不展示私有推理链。全局生成 12 次调用/两轮修复预算由服务端共享预留，不按 Agent 各发一份。 |

| 验收 ID | 需求 | 具体预期 |
|---|---|---|
| F10-AT01 | F10-R01 | 用一份未预置材料生成计划并实际执行至少 Evidence、Designer、Builder、Review 的专业任务；每项有独立上下文/工具权限和真实产物。 |
| F10-AT02 | F10-R02 | 注入跨项目证据、旧输入哈希、未授权工具和不合格交接消息均拒绝；合法产物可追至来源和上游任务。 |
| F10-AT03 | F10-R03 | 中断一个审校分支再恢复，已提交结果复用，不能跳过失败分支；取消/旧 token 不提交新候选。 |
| F10-AT04 | F10-R04 | 并行 Agent 不能超额预留；报告包含失败和重试成本；展示真实委派/工具轨迹，不把预设流程截图冒充执行。 |

语义不确定时交给用户补充或人工审查。Review Agent 只能提问题/建议，不写 content_status=approved。执行事实源为任务表、Agent 子任务与不可变产物；LangGraph checkpoint 是执行恢复辅助。
