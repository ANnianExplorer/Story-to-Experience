# F07 SPEC：不可变版本、局部修改与冲突

> 文档基线；需求已定义，业务验收未执行。设计见 [SDD](../../sdd/features/F07-versions-revisions.md)。

## 范围

任何修改可追溯，保留上一稳定体验；旧基准不静默覆盖，语义变化不复用旧审核。

## 需求

| 需求 ID | 需求 | 必须满足的行为 |
|---|---|---|
| F07-R01 | 不可变快照 | 生成/修改/修复保存父版本、源/事实/蓝图/规格/素材/运行时和调用清单；版本内容不原地修改，质量记录追加。 |
| F07-R02 | 旧基准冲突 | 修订请求要求 base_version_id 等于项目 revision_head；事务认领后由 run_id 预留该修改槽；第二个并发请求确定返回 409。 |
| F07-R03 | 受限局部修改 | 补丁只允许已授权候选的白名单路径；修改受众/提示也需影响分析；事实、来源、必要目标和测试配置不能隐式改写。 |
| F07-R04 | 稳定指针 | 失败不覆盖 stable；选稳定版需技术 passed 与内容 approved；selected 可指未审私有候选，但不能成为公开 stable。 |

## 验收计划

| 验收 ID | 关联需求 | 场景及可观察预期 |
|---|---|---|
| F07-AT01 | F07-R01 | 改写已存在内容哈希被拒；旧版本和报告可回读；相同材料不承诺模型重跑得到相同文字。 |
| F07-AT02 | F07-R02 | 同一旧版本两次修改，首个认领后第二个为 ACTIVE_RUN 或 VERSION_CONFLICT；首个完成后再次旧基准为 VERSION_CONFLICT。 |
| F07-AT03 | F07-R03 | 文案修改列出 diff；改条件触发全局状态检查；语义内容变化使审核 pending；越界路径拒绝。 |
| F07-AT04 | F07-R04 | 失败候选存在但 stable 不变；返回旧合格版保留所有历史；旧失效审核不能用于提升。 |

## 契约与失败行为

过期基准 409；越权/未知路径补丁拒绝；验证失败仍保留候选和问题，但不改变 stable。

通用字段、HTTP 错误和权限取 [公共 API](../api.md)、[状态机](../state-machines.md)、[安全规格](../security.md)；体验执行取 [DSL 契约](../experience-spec.md)。任何新增机制/状态/权限需同步这些规格与相关验收。

## 完成边界

每条 AT 必须记录环境、输入/版本哈希、命令或操作、预期/实际和报告路径。模拟、静态检查、真实 Provider 与真实浏览器证据分开；当前只定义计划，不声称功能通过。状态仅更新 [登记表](../../feature-registry.json)。
