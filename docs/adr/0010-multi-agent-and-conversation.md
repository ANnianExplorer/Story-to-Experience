# ADR-0010：多 Agent 协作与双端 AI 对话进入核心范围

- 状态：Accepted（依据用户本轮明确纠正；设计基线，尚未实现）
- 日期：2026-10-31
- 关联：F03、F04、F06、F08、F09、F10、F11
- 关系：补充 ADR-0001/0004/0005/0007；替代旧方案中“串行单主 Agent 即可”“体验端默认无模型服务”“首版不做 AI 对话”的范围收缩，不废除共享确定性引擎、证据和发布门槛。

## 背景与决策

用户明确要求多 Agent 方案及 AI 对话，并提供赛道 B 评分截图。采用 Coordinator 协调专业 Agent 的架构；创作者通过对话规划/修改，体验参与者通过 AI 导览或角色进行开放文本交流，回答有版本上下文和出处。

多 Agent 是运行系统的业务能力，不表示本次编码助手应启动多个子代理开发。专业 Agent 有独立上下文、工具白名单、输入输出、子任务和追踪；可共用模型服务，不能仅把七个函数换成七个名称。

## 职责

Coordinator、Evidence、ExperienceDesigner、ExperienceBuilder、Review、Repair、Guide 共七种逻辑 Agent。生成侧按依赖编排；候选生成后模型审校与确定性检查可并行后汇合。Guide 为在线体验服务，不重复执行生成链。

## 双端对话与边界

创作者对话使用项目权限，可澄清目标、检索、制定计划、发起新候选和修改；发布仍由明确的用户动作和门槛控制。体验对话只读已发布版本及允许对外的证据投影，可提示、解释、追问、角色回应，不能修改项目、原文或直接判定任务成功。

对话内容不纳入有限状态穷举；确定性验证只覆盖结构化任务逻辑。在线体验具有实时 AI；离线资料包保留固定互动/审核过的知识卡，明确没有实时 AI，不能宣称同等功能。

## 代价与替代

相比单 Agent，本选择增加上下文隔离、交接、并发预算、对话延迟和测试负担。首版采用同一模块化后端和 LangGraph 自定义图承载逻辑 Agent，不为每个 Agent 部署微服务。无限自由协商、多层无界代理和仅预设 FAQ 均不满足本次范围。

## 验证

F10/F11 独立 SPEC/SDD 与评分映射是实施依据。每个真实子任务记录工具、输入输出引用、状态、耗时/费用和恢复；AI 回答测试来源、版本、上下文、未知、提示注入、限流和取消。模型 Review 不等于人工内容批准。参见 [V2 总览](../architecture-and-design-v2.md)。
